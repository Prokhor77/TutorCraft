# ADR-008: Доставка HLS-видео
Статус: принято (MVP) · 2026-09-27

**Контекст.** media-worker кладёт HLS в S3 по ключам `hls/{fileId}/master.m3u8` и `hls/{fileId}/<rendition>/*.ts|m3u8`
(architecture.md §5.2). Плеер запрашивает мастер-плейлист, затем вложенные плейлисты и сегменты по относительным путям.
Pre-signed GET подписывает ровно один объект: подписанный URL мастер-плейлиста не даёт доступа к сегментам,
а переписывать плейлисты с подписью каждого сегмента на каждый просмотр — дорого и ломает кэширование CDN.

**Решение (MVP).**
- `FileMeta.video.hlsUrl` = `${S3_PUBLIC_ENDPOINT}/${S3_BUCKET}/${masterPlaylistKey}` — прямой URL без подписи.
- Бакет по умолчанию закрыт; анонимное чтение разрешено **только** для префикса `hls/`
  (`mc anonymous set download local/$S3_BUCKET/hls` в `infra/minio/init.sh`). Оригиналы и все остальные файлы
  (`t/{tenantId}/…`) по-прежнему доступны только по pre-signed URL после проверки прав.
- Идентификатор `fileId` — UUIDv7 (непредсказуем для перебора на практике, но не является секретом):
  знающий URL может посмотреть видео без входа. Для MVP это принятый риск.

**Прод (P1).** HLS-префикс раздаётся через Cloudflare CDN с подписанными URL/cookie (Cloudflare Signed URLs или
Workers + HMAC-токен с TTL, привязанный к пользователю и `fileId`); прямой анонимный доступ к `hls/` в S3 закрывается,
CDN ходит в origin с собственными учётными данными. `hlsUrl` тогда выдаётся core-api после проверки прав на элемент курса.

**Последствия.** Контракт `hlsUrl` не меняется при переходе на CDN — меняется только базовый адрес и способ подписи.
