# ADR-009: Web frontend (apps/web)
Статус: принято · 2026-09-27

**Контекст.** ARCH-07 требует дизайн-систему (токены + компоненты), отделение бизнес-логики UI от представления
и клиентский кэш с инвалидацией по мутациям. Макеты (Google Stitch) пока недоступны; бэкенд пишется параллельно.

**Решение.**
- Next.js 15 App Router, `output: 'standalone'`. SSR — только публичные витрины `/c/*` (ADR-002, ADR-003); приложение
  клиентское под группой `(app)` с guard'ом по refresh-cookie.
- `/api/v1/*` проксируется Route Handler'ом, а не `rewrites()`: rewrites фиксируются на этапе сборки standalone,
  а `CORE_API_URL` — runtime-конфигурация docker-compose.
- Слои: `lib/api` (fetch-клиент, zod-схемы = типы контракта, Problem Details, single-flight refresh, Idempotency-Key,
  If-Match) → `features/*` (React Query-хуки, инвалидация, оркестрация) → `components/*` (представление) и
  `components/ui` (примитивы Radix без бизнес-логики).
- Все визуальные решения — CSS-переменные в `src/styles/tokens.css` (светлая/тёмная темы, брендинг tenant'а
  переопределяет `--primary*`); перенос макетов = правка токенов.
- Блочный редактор собственный и хранит контрактный `BlockDoc` без промежуточного формата; изображение без `alt`
  не отправляется на сервер (черновик сохраняется локально).
- Офлайн: персистентная очередь операций с исходным Idempotency-Key (сдача, ответы теста, завершение) + service worker
  (network-first для контента, cache-first для статики, очистка при выходе).

**Допущения по контракту** перечислены в `apps/web/README.md` («API assumptions») и должны быть подтверждены
или исправлены в `docs/api/contract.md`.
