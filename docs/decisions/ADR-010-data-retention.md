# ADR-010: Хранение данных удалённых курсов (очистка корзины)

**Статус:** принято. **Связано:** FR-COURSE-07 (корзина), FR-USER-05 (анонимизация, P1), NFR-LEGAL-01, DATA-03.

## Контекст
Курс, удалённый в корзину, через `tutorcraft.trash.retention` (30 дней) физически удаляется заданием `TrashPurgeJob`.
На курс ссылаются данные других модулей. Внешние ключи на `courses` есть только у `enrollments`,
`course_invite_links` и `course_groups`; сдачи, попытки, оценки, заказы и прогресс хранят `course_id` без FK.
Прежняя реализация пыталась выполнить `DELETE` и считала нарушение FK признаком «курс занят». Это давало три проблемы:
- курс только со ссылками-приглашениями или группами никогда не удалялся;
- курс со сдачами/оценками/заказами, но без записей, удалялся, а данные учащихся и платежи оставались без курса;
- выборка «100 самых старых» упиралась в удерживаемые курсы, и очистка переставала продвигаться.

## Решение
1. **Курсы с данными учащихся не удаляются физически.** Данные учащихся — записи на курс (в любом статусе), сдачи,
   попытки тестов, оценки (история оценок append-only, DATA-03), прогресс и завершение курса — и финансовые данные
   (заказы в любом статусе). Их хранят по требованиям закона и учёта оценок: они нужны для подтверждения обучения,
   апелляций, бухгалтерской и налоговой отчётности. Такой курс остаётся в корзине (`deleted_at` задан) и недоступен
   в интерфейсе.
2. **Чистый предикат вместо ошибки FK.** Каждый модуль-владелец данных реализует SPI `courses.spi.CourseDataOwner`:
   `retainsCourse(tenantId, courseId)` проверяет его собственные таблицы; `purgeCourse` удаляет служебные данные
   (ссылки-приглашения, группы, продления сроков, исключения тестов, структуру журнала, отметки просмотров).
   `CoursePurger` в одной транзакции проверяет всех владельцев и, если никто не удерживает курс, вызывает `purgeCourse`,
   удаляет строку курса, затем модули и элементы в MongoDB (ошибка MongoDB откатывает транзакцию, курс обработается
   при следующем запуске).
3. **Обход по курсору** `(deleted_at, id)`: удерживаемые курсы не мешают очистке остальных; ошибка по одному курсу
   записывается в журнал и не останавливает запуск.
4. **Анонимизация — отдельный процесс (FR-USER-05, P1).** Персональные данные удаляются при анонимизации пользователя,
   учебные записи обезличиваются. После истечения сроков хранения учебных и финансовых данных (определяет оператор
   данных; настройка появится вместе с FR-USER-05) удерживаемые курсы можно будет удалить тем же `CoursePurger`,
   когда владельцы перестанут их удерживать.

## Последствия
- Удалённые курсы с учащимися накапливаются в `courses` (строка курса небольшая); контент в MongoDB сохраняется вместе
  с ними, чтобы оценки и сдачи оставались интерпретируемыми.
- Новый модуль, который хранит данные учащихся с `course_id`, обязан реализовать `CourseDataOwner`.
- Ежедневный запуск повторно проверяет удерживаемые курсы (несколько `EXISTS` по индексированным столбцам на курс).
