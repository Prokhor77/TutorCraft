# Руководство администратора

## Установка
См. `README.md` (docker compose). Для продакшна: те же образы, внешние управляемые PostgreSQL 16, MongoDB 7 (replica set), Redis 7, Kafka 3.8 (KRaft), S3-совместимое хранилище; перед web и бакетом `hls/` — CDN (Cloudflare).

## Конфигурация
Все параметры — переменные окружения (`.env.example` — полный список с комментариями). Приложение не стартует с некорректной конфигурацией (ARCH-05). Обязательные секреты: `JWT_SECRET` (≥ 32 символов, общий для core-api и notifier), `DATA_ENCRYPTION_KEY`, пароли БД/Redis/S3. В продакшне `COOKIE_SECURE=true`, `SPRING_PROFILES_ACTIVE=prod`, `SEED_DEMO_DATA=false`.

## Масштабирование
core-api, web, media-worker, notifier — stateless, масштабируются добавлением экземпляров. Ограничения: Telegram-опрос (`TELEGRAM_POLLING_ENABLED`) включать ровно в одном экземпляре notifier; параллелизм media-worker ≤ числу партиций топика (6).

## Резервное копирование (NFR-REL-02, цель RPO ≤ 15 мин, RTO ≤ 4 ч)
- PostgreSQL: непрерывная архивация WAL (pgBackRest/wal-g) + ежедневный базовый бэкап.
- MongoDB: ежедневный `mongodump --oplog` + снапшоты тома; oplog-окно ≥ 24 ч.
- S3: версионирование бакета + репликация в другой регион.
- Проверка восстановления — ежемесячно на отдельном стенде: восстановить все три хранилища на одну метку времени, поднять compose, прогнать e2e.

## Обновление
Миграции Flyway применяются автоматически при старте core-api и совместимы назад (expand/contract, NFR-REL-03): сначала обновляются экземпляры core-api по одному, затем web и воркеры.

## Журнал активности (Администрирование → Активность)
Каждый запрос к API (кто, что, с какой страницы, статус, длительность), переходы по страницам и ошибки в браузере
выбранной школы. Отличие от «Журнала аудита»: аудит — только бизнес-изменения и хранится долго, активность — всё подряд,
операционный журнал с коротким сроком хранения.

- **Как найти ошибку пользователя.** При сбое сервера пользователь видит «Код ошибки: …» — вставьте его в поле
  «Код ошибки (request id)». Или выберите фильтр «Ошибки» / нажмите маршрут в блоке «Где чаще всего падает».
- **Трассировка** открывает запись целиком (обработчик, параметры пути, тип и сообщение ошибки, стек вызовов) и действия
  того же пользователя за 30 минут до и 5 минут после (для анонимных — той же вкладки браузера или IP). Клик по шагу
  перестраивает трассировку вокруг него.
- **Действия без входа** (вход, регистрация, публичные страницы) не принадлежат школе — переключатель «Показывать действия
  без входа».
- Конфиденциальность: тела запросов, query-строки, пароли и токены не пишутся; e-mail и токены в текстах ошибок маскируются.

Настройки (`.env`): `ACTIVITY_LOG_ENABLED` (по умолчанию `true`), `ACTIVITY_LOG_READS` (`false` — не писать успешные
GET, чтобы уменьшить объём), `ACTIVITY_LOG_RETENTION` (ISO-8601, по умолчанию `P30D`; очистка ежедневно в 03:37 UTC).
Запись асинхронная, пачками; при переполнении буфера записи отбрасываются — метрика `tutorcraft_activity_log_dropped_total`.
Объём ориентировочно 0,5–1 КБ на запрос: 100 тыс. запросов в день × 30 дней ≈ 1,5–3 ГБ в PostgreSQL.

## Мониторинг
`/health/live`, `/health/ready` (core-api, воркеры), метрики Prometheus `/actuator/prometheus`, JSON-логи с `traceId` и `requestId`. Kafka DLQ-топики `*.dlq` — алерт на ненулевой размер.
